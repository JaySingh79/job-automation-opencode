# Hirist bottlenecks (Playwright extension browser, 2026-10-08)

- Job-detail pages (`/j/<slug>-<id>`) never hydrate: `_next/static/chunks/app/j/[jobslug]/page-*.js` fails with ERR_PROXY_CONNECTION_FAILED on every load (5+ attempts, short + long URL forms). Category pages load fine. Workaround: use gladiator APIs directly (same-origin fetch works).
- `browser_click` on MUI combobox (experience filter) and on job cards / Apply buttons times out on stability checks (3+ occurrences). Workaround: `browser_evaluate` dispatchEvent/click.
- Endpoints found: GET `gladiator.hirist.tech/job/category/?minexp=&maxexp=&page=&size=` (loose exp filter — enforce max<=3 client-side), GET `job/detail?jobcode=`, GET `job/assessment?jobcode=` (returns question strings only), POST `job/apply?jobcode=` with `{}` applies one-click (no review step).
- Assessment-gated jobs return 400 ASSESSMENT_REQUIRED; submit endpoint for answers not discoverable via API (POST /job/assessment hangs, PUT 404, /submit /answer /user/assessment 404). Needs the detail-page form → blocked while detail JS is proxy-failing.
- 2026-10-10 UPDATE: detail-page proxy failure is TRANSIENT — `/j/<slug>-<id>` hydrated fully this run after 5+ prior failures. Direct screening URL `https://www.hirist.tech/job/<id>/screening?ref=red_old` loads the form without clicking Apply (4/5 parked assessments fixed this way). Always spend the ONE render-check navigate before parking.
- Yes/No screener options are generic divs, not radios — `browser_click` on them silently no-ops (Next stays disabled; 3 occurrences: 1670614, 1636656, 1673189-needed-repass). Workaround: `browser_evaluate` dispatch pointerdown/mousedown/mouseup/click on the option scoped to its question label, then verify Next enabled.
- `browser_click` on Next races a form re-render that clears Yes/No state (2 occurrences). Workaround: select options + click Next atomically in ONE `browser_evaluate` (select, wait ~800ms, DOM-click Next, wait 3.5s, assert `/job/applied` URL). Justification documented per run; still prefer `browser_click` first.
- Screener questions can CHANGE between runs (1665996: Yes/No set → "Which IIT / JEE rank" textboxes). Never trust parked questions; re-read the live form. JEE rank is not in profile — queue to human, never invent.
